# NESMA检查代理需求规范

## 1、总体要求

### 1.1 建设目标

自动化验证：将NESMA交付物的检查要点数字化、规则化，实现从人工逐项核对到系统自动检查的转变，大幅提升检查效率。

AI赋能：利用AI能力自动识别交付物中的功能组件、评估复杂度，降低功能点分析员的手工工作量。

客观评估：以GB/T 42588-2023及ISO/IEC 24570标准为基准，提供统一、可重复的检查规则，消除人工评审的主观差异。

持续改进：支持检查规则的持续优化和知识沉淀，不断提升检查的准确性和覆盖率。

## 1.2 适用范围

适用于采用NESMA功能点分析法进行工作量评估的各类软件项目。

支持不同分支的不同模板要求。

本工具不能完全替代人工评审，而是作为评审的辅助手段，提供合规性检测、一致性分析和智能建议。

## 2.功能需求

### 2.1模板文档管理

模板格式：需求说明书、功能计数表和测试报告需遵循客户提供的模板。

模板版本管理：工具应支持上传并识别当前项目使用的模板版本，不同分支的项目可使用不同模板；模板变更时需提示用户重新校准检查规则。

文档解析：根据模板中的固定标签（如“功能编号”“ILF描述”等）自动定位并提取内容，提升要素识别准确率。

### 2.2 跨文档一致性检查

文档交叉校验：比对需求说明书模板、功能计数表模板、测试报告模板中相同功能点定义和计数是否一致。

模板间字段映射：自动识别不同模板中对应的字段，保证文档间的一致性。

### 2.3 规则检查

以NESMA的国标为基础，整理检查清单，按照检查清单进行判断。

### 2.4 AI智能能力

该模块利用AI大语言模型的分析能力，对NESMA交付物进行更深层次的语义理解和智能分析，提升检查的深度和智能化水平。

#### （1）智能识别与提取

AI模型能够从需求文档或交付物文本中智能识别潜在的功能组件（ILF/EIF/EI/EO/EQ），辅助核对人工枚举是否完整。

能够从自然语言描述中识别逻辑文件与被维护应用的归属关系（即区分ILF与EIF），辅助校验识别准确性。

能够从功能描述中识别完整、独立、对用户有意义的最小业务操作单元（基本过程），辅助事务功能识别。

#### （2）语义一致性检查

判断交付物中各功能组件描述之间的逻辑一致性，识别潜在矛盾或不一致之处。

基于语义分析检测交付物中可能遗漏的功能组件，并与功能点枚举清单进行智能比对。

分析交付物中的功能描述与NESMA分类定义之间的匹配度，识别分类错误，将交付物中的功能描述与NESMA类别定义进行概念对齐，判定EI、EO、EQ等类别划分是否准确。

检测交付物中是否存在表述模糊、歧义性过高的描述，提出澄清建议。

检测交付物中是否存在复用或修改等功能调整场景，并提示该调整是否被合理计入功能点计数。

#### （3）智能审核与建议

对交付物中发现的问题给出智能化的改进建议和修正方案

基于历史检查数据，学习并优化检查规则和AI模型的判定策略

提供对单个功能组件识别决策的可解释性说明，向用户解释AI判定结果的依据

#### （4）不确定性处理

AI模型对识别结果提供置信度评分，低于阈值的识别结果标记为“待人工确认”。

支持人工对AI识别结果进行校正，并将校正结果作为训练数据用于模型迭代优化。

### 2.4. 报告生成

综合评估报告：汇总所有检查结果，输出综合质量评分及通过/有条件通过/不通过结论，包含按优先级排序的改进建议清单。

问题专项报告：根据检查项的内容，对不符合的项，列出所有问题的位置。必要时可以给出 改进建议。

## 3.非功能需求

1. ### 性能

单文档处理时间：≤10分钟（1000行以内）

并发用户：支持至少10个用户同时使用

2. ### 可用性

解析成功率 符合模板的DOCX文件解析成功率≥99%

错误提示 所有异常情况提供明确的中文提示，模板校验失败时需具体指出是哪个章节/表格/标签缺失

3. ### 合规性

NESMA标准：所有检查规则严格遵循GB/T 42588-2023

4. ### 可扩展性

AI模型可替换 支持更换不同的大语言模型

规则热更新 NESMA检查规则支持在线更新，无需重启系统

模板适配扩展 允许管理员上传新的客户模板，并通过图形化界面标记模板中的关键字段位置（如“ILF表格起始行”“功能ID列标”等），实现无代码适配新模板。
