# NESMA Check Skill 路线图

**版本**: 2.0.0
**更新日期**: 2026-06-02

## 项目概览

NESMA Check Skill 是一个自动化合规检查引擎，用于验证工作量评估文档是否符合 NESMA（Netherlands Software Metrics Association）标准。基于 GB/T 42588-2023 和 ISO/IEC 24570。

## 阶段时间线

```text
Phase 1 ──→ Phase 2 ──→ Phase 3 ──→ Phase 4 ──→ Phase 5+
规则引擎     架构重设计   输出质量     文档更新     增强功能
 ✅ 已完成    ✅ 已完成    ✅ 已完成    ✅ 已完成    📋 规划中
```

## Phase 1: 规则引擎重建 ✅ 已完成

**目标**: 将分散的规则文本重建为标准化 YAML 规则体系，每条规则有完整的检查语义。

**状态**: ✅ 已完成（2026-05-28）

**产出物**:

| 产出物 | 路径 | 说明 |
|--------|------|------|
| 基础规则 YAML | `rules/base/{category}/` | 62 条规则，按类别组织 |
| 组织覆盖规则 | `rules/orgs/ORG_B/` | 工程项目 + 新需求项目覆盖 |
| 规则路由器 | `references/router.md` | 规则加载逻辑和优先级 |
| 规则 ID 映射 | `references/rule-id-mapping.md` | 旧编号 → 新编号映射 |

**关键变更**:
- 一个文件一条规则（DF-001.yaml ~ FM-012.yaml）
- 按类别自动发现加载：data-functions / transaction-functions / cross-validation / format
- `_base-rules.md` 重命名为 `_base-rules-reference.md`（不再直接加载）

## Phase 2: 架构重设计 ✅ 已完成

**目标**: 明确两层检查架构的职责边界和接口，程序化层处理确定性问题，语义层处理判断性问题。

**状态**: ✅ 已完成（2026-06-02）

**产出物**:

| 产出物 | 路径 | 说明 |
|--------|------|------|
| 工作流定义 | `references/main-workflow.md` | 唯一工作流来源，7 步流程 |
| LLM Prompt 模板 | `references/llm-prompts.md` | 语义层检查 Prompt（19 条规则全覆盖） |
| LLM 检查配置 | `references/llm-check-config.md` | 置信度阈值和冲突解决策略 |
| SKILL.md | `SKILL.md` | 精简版，只引用不重复 |

**两层架构**:

| 层 | 职责 | 规则数量 | 执行方式 |
|----|------|----------|----------|
| Layer 1: 程序化检查 | 格式、编号、必填字段、数值范围 | ~38 项 | 直接检查 |
| Layer 2: LLM 语义检查 | 分类准确性、复杂度评估、跨文档一致性 | ~24 项 | LLM 会话 |

**关键变更**:
- SKILL.md 工作流部分只引用 main-workflow.md
- 语义层结果优先，记录冲突供人工审核
- 置信度 < 0.6 标记为"待复核"

## Phase 3: 输出质量提升 ✅ 已完成

**目标**: 从 pass/fail 升级为可操作的检查报告，每个发现包含原因、标准引用和修改建议。

**状态**: ✅ 已完成（2026-06-02）

**产出物**:

| 产出物 | 路径 | 说明 |
|--------|------|------|
| 报告模板 | `references/report-template.md` | 三级结构：摘要→详情→建议 |
| 删除脚本 | `scripts/` | 已清空，验证改为 prompt 约束 |

**报告结构**:

```text
摘要（统计表格）
  ↓
详情（8 列表格：序号/分类/检查项/结果/位置/说明/严重级别/建议）
  ↓
建议（按严重级别分组，含标准引用和修改建议）
```

**关键变更**:
- 输出格式：8 列表格，位置使用分号分隔
- 每个"不通过"结果必须包含修改建议和标准引用
- 三级结论：通过 / 有条件通过 / 不通过
