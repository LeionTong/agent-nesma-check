# 1 核减率计算规则
功能点值 = { 类别对应的值 * 重用程度对应的值 * 修改类型对应的值 }  
调整后功能点 = { 所有功能点值之和 }

评审前的调整后功能点 = { 原始功能点拆分表中的3C单元格的值 }
评审后的调整后功能点 = { 评审后的副本的功能点拆分表中的3C单元格的值 }

核减率 = { ( 评审前的调整后功能点值 - 评审后的调整后功能点值 ) / 评审前的调整后功能点值 }

# 3 类别/重用程度/修改类型的取值依据
## 3.1 基本原则
- 以原有的拆分表填写的类别，重用程度，修改类型为基础，在此基础上根据如下规定调整取值，如果不涉及如下规定的，默认为原始取值不变动。
- 注意：只能比原拆分表的取值低或者同级，不能比原拆分表的取值高。例如原拆分表将一个类别标记为EQ(4),但经过我们解析判断其实应取值为EO(5)，那么在计算有效功能点时还是按照原拆分表的EQ(4)进行计算；例如原拆分表的重用程度标记为高，经过解析判断为低，那么在计算有效功能点时还是按照原拆分表进行计算；例如原拆分表的修改类型标记为删除，经过解析判断为修改，那么在计算有效功能点时还是按照原拆分表进行计算；

##  3.2 类别
- 读取和解析“功能项描述”和“功能点计数项名称”，结合国标GB-T42588-2023中对ILF,ELF,EI,EO,EQ的定义，判断每一行的功能属于哪种类别，确定类别后，根据2.1的相关内容，确定类别对应的取值。

## 3.3 重用程度
- 多端系统中的同一功能，例如：在IOS、安卓、PC端都开发了用户新增功能，那么PC端的计取重用程度为低，IOS、安卓端计取重用程度为高；
- 通用组件功能：例如：依赖于导出组件、导入组件、上传组件、下载组件等通用组件实现的用户信息导出、资源信息导入、个人资料上传、审计报告下载等功能计取重用程度为高；
- 功能类型为修改或者删除的计取重用程度为高；
- 依赖于同一模型，功能目的不同的功能，例如：XX新增、XX修改、XX删除、XX启用、XX激活，那么XX新增计取重用程度为低，其余功能计取重用程度为高；
- 功能高度类似，但有细微差别的功能，例如：资料管理员审核/部门经理审核（两者功能有差别）、开卡数据日报/开卡数据月报，那么资源管理员审核、开卡数据日报计取重用程度为低，其余2个功能计取重用程度为高；
- 同一页面存在外键关联的查询功能，例如：用户信息查询、用户详情查询，那么用户信息查询计取重用程度为低、用户详情查询计取重用程度为高。

## 3.4 修改类型
1. 新增代表的含义是该功能在往期没有建设过，本次新增开发，新增的逻辑、计算方式、属性等分步骤不能算作该功能处理的新增，例如：以前的
用户管理功能中只具备了增删改查功能，本次新增开发导出功能，那么导出功能的送审类型就应该为新增；以前登录功能中只具备账号密码登录功能，
本次新增开发SIM方式登录功能（账号密码登录和SIM登录属于2个独立的事务功能），那么SIM方式登录功能的送审类型就应该为新增。误区：如果
以前的财务报表汇总功能中，没有统计员工的差旅费用，本次新增统计差旅费用数据，那么统计差旅费用只是财务报表汇总功能的其中一个分步骤，
座椅财务报表汇总功能的类型应该为修改；"
2. 修改代表的含义是该功能在往期已经建设过，本次进行增强开发，例如：在以前的用户查询功能增加筛选项用户属于省份、地市、区县，以便提
高查询效率，用户查询功能在往期项目中已经建设过了，本次仅是增加筛选条件，用户查询功能的送审类型应该为修改。误区：不要将新增开发的修
改功能当做送审类型为修改，例如：以前账号管理功能只具备账号新增、查询功能，不具备账号修改功能，本次新增开发账号修改功能，那么账号修
改功能的送审类型为新增而不是修改；一个功能在同一次开发中优化多个不同的分步骤，只能计数为一次优化，例如：在原来的用户信息查询功能中，
增加筛选条件省份、地市、区县、前端界面呈现增加用户户籍字段、增加按照年龄从大到小的排序逻辑，虽然改造了3个不同的点，但是根据基本过程
完整性的原则来说，只能计取为1个EO；一个功能在不同批次开发中优化可分别计取，但是需提供相关材料证明是在多批次的开发中实现的。"
3. 删除代表的含义是该功能已经在往期建设过，本次将该功能下线，例如：为了加强产品质量原因的真实性，将原来建设过的产品审核记录修改功能下
线，所以产品审核功能本次的送审类型应该为删除。误区：不要将原本功能中删除某条处理逻辑或者某个数据当做该功能送审类型为删除，例如：将
原本告警统计功能中剔除自然灾害类型的告警逻辑、将原本审核功能中的通过、驳回、待定三个按钮剔除待定按钮，那么告警统计功能、审核功能的
送审类型应该为修改而不是删除。"

## 3.5 其他

请参考checklist中的内容，如果拆分表的功能违背checklist中的规则，按照 type_modify、reusability_modify、change_modify、function_point_count进行功能点计数。
- type_modify表示要调整类别；
- reusability_modify表示要调整重用程度；
- change_modify表示要调整修改类型；
- function_point_count表示功能点计数。
