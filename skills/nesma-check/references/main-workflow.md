# NESMA 文档检查流程

**版本**: 3.0.0
**日期**: 2026-06-23
**说明**: 唯一的工作流定义来源。SKILL.md 只引用本文件。

## 整体流程

```
1. 接收文件路径 + 解析参数（--org/--project-type）
2. 检测 docx/xlsx skills 可用性
3. 加载规则（按 router.md 逻辑，自动发现 checklist/）
4. 读取文档内容 + 识别文档类型
5. 执行分项检查（两层架构）
6. 生成检查报告（三级结构：摘要→详情→建议）
7. 验证报告格式
```

## Step 1: 接收并验证文件 + 解析参数

### 1.1 解析文件路径和输出参数

- 解析用户输入的文件路径（支持单文件、多文件、目录三种输入形态）
- 解析 `--output` 参数（可选，指定报告输出路径或目录）
- 解析报告输出目录：
  - 显式指定 `--output` 为文件路径 → 取该文件所在目录
  - 显式指定 `--output` 为目录路径 → 取该目录
  - 省略 `--output` → 取**首个输入路径**的所在目录（单文件输入取该文件所在目录；多文件输入取首个文件所在目录；目录输入取该目录本身）
- 区分 `--output` 是文件路径还是目录路径：以末尾分隔符（`/` 或 `\`）结尾、或无文件扩展名者视为目录路径
- 相对路径输入按原样解析所在目录，不强制转绝对路径
- 验证文件是否存在
- 确认文件格式（.doc, .docx, .xls, .xlsx, .md）

### 1.2 解析规则参数

- 解析 --org 参数（组织分支）
  - 可选值：`ORG_B`、`ORG_A`
  - 默认值：无（只用基础规则 `checklist/Base-All-*.yaml`）
- 解析 --project-type 参数（项目类型）
  - 可选值：`engineering`（工程类）、`new_demand`（新需求类）
  - 默认值：无（所有规则）

### 1.3 参数验证

- 验证参数值是否在可选值范围内
- 验证参数组合是否有效

## Step 2: 检测 docx/xlsx skills 可用性

检查 docx skill 和 xlsx skill 是否已安装并可用：

- 如果处理 .docx 文件：检查 docx skill 是否可用
- 如果处理 .xlsx 文件：检查 xlsx skill 是否可用
- **如果 skill 不可用：显式提醒用户安装**

### 错误信息示例

```
错误: docx skill 未安装，请先安装 docx skill 后再使用 nesma-check
错误: xlsx skill 未安装，请先安装 xlsx skill 后再使用 nesma-check
```

### 后续处理

- **检测通过**：继续 Step 4（读取文档）
- **检测失败**：立即报错终止执行，不进行后续检查

## Step 3: 加载规则

详见 `router.md` 中的规则加载逻辑。

**关键变化（v3.0）**：

- 规则从 `checklist/` 目录自动发现加载（10 个扁平 YAML 文件，153 条规则）
- 不再加载 `GB-T42588-2023.md`（2440 行国标全文）
- 组织规则按 `--org` 参数从 `checklist/Orgs-{org}-*.yaml` 加载
- 项目类型按规则内部 `scope` 字段过滤

## Step 4: 读取文档内容 + 识别文档类型

### 4.1 使用 docx skill 读取 .docx 文件

调用 docx skill 读取文档，提取段落和表格信息：

**位置格式**:

- 段落：`§{章节号} #P{段落号}`（如 `§3.2.1 #P15`）
- 表格：`§{章节号} 表格{序号} 行{行号} 列{列号}`

### 4.2 使用 xlsx skill 读取 .xlsx 文件

调用 xlsx skill 读取工作簿，提取单元格信息：

**位置格式**:

- 单工作表：`行{Row}; 列{Col}`（如 `行25; 列C`）
- 多工作表：`[{sheet_name}] 行{Row}; 列{Col}`（如 `[规模估算] 行25; 列I`）

**注意**：位置格式使用**分号**分隔，不是逗号。

### 4.3 读取 .md 文件

直接读取文本文件：

**位置格式**: `行{Row}`（如 `行42`）

### 4.4 识别文档类型

根据内容特征判断文档类型：

| 特征                              | 文档类型                                       |
| --------------------------------- | ---------------------------------------------- |
| 包含"需求"、"功能"、"ILF"         | 需求说明书 (srs)                               |
| 包含"功能点"、"复杂度"、"DET/FTR" | 功能清单拆分表 (function_breakdown)            |
| 包含"测试用例"、"覆盖率"、"TC"    | 测试报告 (test_report)                         |
| 包含"技术"、"架构"、"接口"        | 技术规范书 (technical_specification)           |
| 包含"系统概详要设计"、"ORG_A"    | 系统概详要设计说明书 (spds)（ORG_A 特有）     |
| 包含"需求评审"、"评审意见"        | 需求评审表 (demand_review_form)（ORG_A 特有） |
| 包含"汇报"、"PPT"、"汇报材料"     | 汇报PPT (ppt)（ORG_A 特有）                   |

如果无法识别，输出"未知文档类型"。

## Step 5: 执行检查（两层架构）

```
┌─────────────────────────────────────────────────────────────┐
│                    Step 5: 执行分项检查                       │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Layer 1: 程序化检查 (~80 项)                                 │
│  ├── 执行方式: 直接检查文档内容                                │
│  ├── 规则: checklist/ 中 layer=programmatic 的规则          │
│  └── 检查项: 格式、编号、必填字段、数值范围、提交完备性          │
│                                                              │
│  Layer 2: LLM 语义检查 (~73 项)                              │
│  ├── 执行方式: 复用当前 agent LLM 会话                       │
│  ├── 规则: checklist/ 中 layer=semantic 的规则              │
│  └── 检查项: 分类准确性、复杂度评估、跨文档一致性               │
│                                                              │
│  结果融合: 语义层结果优先，记录冲突供人工审核                   │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 5.1 Layer 1: 程序化检查

直接执行以下类别的程序化检查：

| 类别                 | 规则数量 | 检查内容                                         |
| -------------------- | -------- | ------------------------------------------------ |
| Base-All-Data        | ~5 项    | DET 定义、RET 计数、命名规范、唯一性             |
| Base-All-Transaction | ~10 项   | DET 定义、FTR 计数、基本过程完整性               |
| Orgs-{org}-Format    | ~45 项   | 位置格式、列数、编号连续性、命名规范、提交完备性 |
| Orgs-{org}-Cross     | ~10 项   | 层级对应检查、跨文档对齐                         |

**执行方式**：直接检查文档内容，不依赖 LLM。

### 5.2 Layer 2: LLM 语义检查

对于需要语义理解的检查项，调用当前会话的 LLM：

| 类别                 | 规则数量 | 检查内容                                |
| -------------------- | -------- | --------------------------------------- |
| Base-All-Data        | ~6 项    | 复杂度矩阵、ILF/EIF 区分、ILF-EI 关联   |
| Base-All-Transaction | ~41 项   | 基本过程识别、EI/EO/EQ 分类、独特性判定 |
| Orgs-{org}-Data      | ~10 项   | DET 计数规则、FTR 识别规则              |
| Orgs-{org}-Format    | ~6 项    | 功能项描述合规性、重用程度判定          |
| Orgs-{org}-Cross     | ~5 项    | 跨文档一致性、架构图对比                |

**执行方式**：详见 `llm-prompts.md` 中的 Prompt 模板。

### 5.3 结果融合策略

当程序化检查和语义检查结果冲突时：

1. **语义层结果优先**（因为语义层可以理解上下文）
2. **记录冲突到报告**（供人工审核）
3. **冲突时置信度降低**（标记为"待确认"）

### 5.4 LLM 置信度机制

| 置信度 | 范围   | 处理方式           | 报告展示                              |
| ------ | ------ | ------------------ | ------------------------------------- |
| 高/中  | >= 0.6 | verdict 直接采用   | ✅ 通过 / ❌ 不通过                   |
| 低     | < 0.6  | verdict + "待复核" | ⚠️ 通过,待复核 / ⚠️ 不通过,待复核 |

## Step 6: 生成检查报告（三级结构）

### 6.1 报告结构

```markdown
## 摘要

- 总检查项: 153
- 通过: xx (xx%)
- 不通过: xx (xx%)
- 不适用: xx (xx%)
- 整体结论: 通过 / 有条件通过 / 不通过

## 详情

| 序号 | 规则ID | 检查项 | 结果 | 位置 | 说明 | 严重级别 | 建议 |
|------|--------|--------|------|------|------|----------|------|
| ... | ... | ... | ... | ... | ... | ... | ... |

## 建议

### Base-All-Transaction-012: 基本过程识别规则检查

- **位置**: 行 45; 行 67
- **原因**: 功能未细分到增删改查级别，不满足基本过程定义
- **标准**: GB/T 42588-2023 §9.1 定义外部输入
- **建议**: 将用户管理拆分为用户新增、用户修改、用户删除、用户查询四个独立的基本过程
```

### 6.2 输出格式规范

**表格列定义（8 列）**：

| 列名     | 说明                                                       |
| -------- | ---------------------------------------------------------- |
| 序号     | 检查项编号（001, 002, ...）                                |
| 规则ID   | 规则标识符（如 Base-All-Data-001, Orgs-ORG_B-Format-063） |
| 检查项   | 检查内容描述                                               |
| 结果     | 通过/不通过/不适用                                         |
| 位置     | 行号引用（分号分隔）                                       |
| 说明     | 发现详情                                                   |
| 严重级别 | error/warning/info                                         |
| 建议     | 具体修改建议                                               |

**位置格式规范**：

| 场景         | 格式                 | 示例                                  |
| ------------ | -------------------- | ------------------------------------- |
| 单个位置     | `行{Row}`          | `行302`                             |
| 多个位置     | 分号分隔             | `行302; 行405; 行452`               |
| 超过10个位置 | 分号分隔，显示前10个 | `行302; 行405; 行452; ... (共52行)` |

**强制约束**：

1. **必须列出所有行号** — 当检查项涉及多行时，`位置` 列必须列出每一行的行号
2. **使用分号分隔** — 多个位置之间用 `; ` 分隔
3. **超出显示限制时** — 超过10行时显示前10行，并在末尾注明 `... (共XX行)`
4. **禁止简写为"多行"** — 绝对不能只写 `多行`、`行多种`、`共XX行` 而不列出具体行号

### 6.3 报告写入

- 将报告写入输出目录：
  - `--output` 指定文件路径 → 写入该文件路径
  - `--output` 指定目录路径 / 省略 `--output` → 在解析得到的输出目录下自动生成文件名
- 自动生成文件名格式：`NESMA合规性检查报告-YYYYMMDD-HHmm.md`
  - 时间戳精确到分钟，使用执行检查时的本地日期与时间
  - 示例：2026-06-25 14:30 生成的报告 → `NESMA合规性检查报告-20260625-1430.md`
  - 该格式同时适用于显式指定目录路径与省略 `--output` 两种场景（统一规则）
- 输出目录不存在时：先创建目录，再写入报告文件
- 同分钟内重复运行生成的文件名相同：覆盖已存在的同名文件（与显式路径已存在时的覆盖行为一致，不报错）

### 6.4 对话输出策略

报告写入文件后，对话界面 SHALL 仅显示写入的文件路径与检查摘要，不贴报告全文：

- **文件路径**：写入的报告文件路径（绝对或相对，与输入路径形态一致）
- **检查摘要**：通过 / 不通过 / 不适用计数 + 整体结论（通过 / 有条件通过 / 不通过）
- **不贴全文**：报告详情（规则表格、改进建议等）仅在文件中，对话界面不重复输出

此策略在显式指定 `--output` 与省略 `--output` 两种场景下行为一致。

## Step 7: 验证报告格式

在报告生成后自动验证：

### 7.1 检查表格式验证

- 表格必须有 8 列
- 列顺序：序号、规则ID、检查项、结果、位置、说明、严重级别、建议
- 每行必须有 8 个单元格

### 7.2 输出范围验证

- 报告必须包含 `*本报告由 NESMA Check Skill v3.0.0 自动生成*` footer
- 必须存在 `**输出终止标记**`
- Footer 后不得存在额外内容

**验证失败**：阻止报告生成，输出错误信息并要求修正。

## 错误处理

| 场景               | 处理方式                                                                               |
| ------------------ | -------------------------------------------------------------------------------------- |
| 文件不存在         | 报错：文件路径无效                                                                     |
| 参数值不合法       | 报错：参数值不在可选范围内                                                             |
| docx skill 不可用  | 报错：docx skill 未安装，请先安装                                                      |
| xlsx skill 不可用  | 报错：xlsx skill 未安装，请先安装                                                      |
| 规则 YAML 格式错误 | 报错：提示具体文件和错误信息                                                           |
| 空文档             | 警告后继续检查                                                                         |
| 大文档             | 分片处理后合并结果                                                                     |
| 写入文件失败       | 报错：无法写入报告文件，说明原因（含默认目录无写入权限的场景，不静默降级为仅对话显示） |
| LLM 服务不可用     | 阻塞等待，超时后报错（不降级运行）                                                     |
