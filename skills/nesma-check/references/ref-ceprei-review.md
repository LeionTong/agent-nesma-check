| 7 | 审计材料获取 | 功能项填报 | 定义逻辑文件 |  | 逻辑文件是用户可识别的持久性的逻辑数据组。它满足以下特征：被当前计数的应用程序所使用，且被应用程序所维护；内部逻辑文件，被当前应用程序维护；外部接口文件，被其他应用程序维护 |
| 8 | 审计材料获取 | 功能项填报 | 逻辑文件定义关键字解析 |  | 1.用户可识别的逻辑数据组：经验丰富的用户认为是有意义和有用的单元或对象的一组数据，等价于数据建模中的对象类型，站在用户角度识别而非技术角度识别，是概念模型中识别的文件，并非数据库文件或物理文件；2.持久性：在应用程序使用文件之后它将始终保持存在，可再次使用，与只能使用一次的其他数据不同；3.被使用：数据在实际应用中被使用到；4.维护：可以添加、更改或删除数据，无任何程序维护则不是逻辑文件 |
| 9 | 审计材料获取 | 功能项填报 | 逻辑文件识别的两个重要概念 | 逻辑差异 | 无逻辑差异的数据实体不应该分拆识别逻辑文件；无差异的子类型、不同的记录值，不能判定为独立的逻辑文件；示例：资产管理系统中，固定资产和流动资产无逻辑差异则合并为1个资产信息逻辑文件，有逻辑差异则拆分为2个独立逻辑文件 |
| 10 | 审计材料获取 | 功能项填报 | 逻辑文件识别的两个重要概念 | 从属关系 | 从属关系的数据实体不应该分拆识别逻辑文件；从属的子表、无业务字段的关系表、数据实体的从属属性信息，不能独立计数为逻辑文件；示例：设备信息的属性字段、发票明细（从属于发票信息）均不能独立计数为逻辑文件 |
| 11 | 审计材料获取 | 功能项填报 | 逻辑文件识别关键字 |  | 1.常见逻辑文件关键字：业务数据类（用户、信息、产品、栏目、公告、公文、任务、项目、实验室、客户群、分组等）；引用数据类（规则、权限、标签、流程文件等，用户可管理维护）；2.常见非逻辑文件关键字：动作类（新增、删除、修改、列表、视图、报表、统计、排序等，文件应为名词）；临时文件（导出文件、导入文件、排序文件、输出报表、统计文件、输出excel、文件系统文件、U盘文件、光盘文件、上传的文件等）；属性名（*名称、*型号、长度、生日、地址、数量、颜色、高度、容量等）；3.常见存疑关键字：子表（明细、详单）、关系表（对应表、关系表）、子类型（某*类产品、某型号类型、多次出现类似重复后缀） |
| 12 | 审计材料获取 | 功能项填报 | 定义基本过程 |  | 基本过程是对用户有意义的最小业务操作，满足两个条件：1.功能对用户有独立完整的意义，并且执行了一个完整的信息处理过程；2.功能执行后，应用程序处于一个稳定的状态 |
| 13 | 审计材料获取 | 功能项填报 | 基本过程定义关键要点 | 最小的功能单元 | 需要细分需求，不能将子系统、模块等过大的功能单元作为基本过程，需细分到增、删、修改、查询级别；示例：用户、角色管理需拆分为用户管理、角色管理，再进一步拆分为增删改查的最小单元 |
| 14 | 审计材料获取 | 功能项填报 | 基本过程定义关键要点 | 对用户有意义 | 必须站在用户的业务视角而非技术视角，必须属于用户需求，超出用户需要的、镀金的需求不应计数；示例：工作流引擎的定义工作流程功能，若超出用户公文审核的需求，不应计算为基本过程 |
| 15 | 审计材料获取 | 功能项填报 | 基本过程定义关键要点 | 独立完整 | 不可过分拆分功能，一个完整的提交-处理过程不能分拆；示例：修改员工信息的姓名、地址、联系方式，属于一个完整的员工修改功能，不能拆分为三个独立的基本过程 |
| 16 | 审计材料获取 | 功能项填报 | 基本过程定义关键要点 | 自包含 | 在之前或之后不需要任何的启动、验证、完成等操作，装载、格式检查、出错提示等均不属于基本过程；示例：项目活动工作量填报前的数据检测，属于填报功能的一部分，不能独立计数为基本过程 |
| 17 | 审计材料获取 | 功能项填报 | 基本过程定义关键要点 | 功能执行后应用程序进入稳定状态 | 操作有结果（成功/失败）、数据完整稳定，操作人员可转其他操作，掉电/重启不会丢失数据；示例：Powerpoint插入图形的所有设置步骤，只有保存后才进入稳定状态，整体计为一个基本过程 |
| 18 | 审计材料获取 | 功能项填报 | 基本过程识别常识 |  | 1.基本过程应包含从开始到结束所遇到的所有正常和异常情况，审核通过/不通过、录入数据的存在/不存在判断，均属于同一个基本过程，不能拆分；2.多步骤录入数据若仅有一处提交，所有步骤服务于一个基本过程，计为一个外部输出，不能按步骤拆分计数 |
| 19 | 审计材料获取 | 功能项填报 | 基本过程分类 |  | 1.EI外部输入：处理来自边界外的数据或控制信息的基本过程；2.EQ外部查询：向应用边界之外发送简单数据的基本过程；3.EO外部输出：向应用边界之外发送通过复杂处理的数据或者控制信息的基本过程 |
| 20 | 审计材料获取 | 功能项填报 | 基本过程识别错误 |  | 1.误识别：程序的步骤、出错、提示、校验、检查等不属于基本过程，将文件/属性等识别为基本过程；2.拆分识别：步骤拆分、数据分类拆分、输入和响应拆分、字段拆分等；3.重复识别：统一识别范围内不同模块重复识别、非新建项目的已有功能重复识别 |
| 21 | 审计材料获取 | 功能项填报 | EI定义及识别规则 |  | 外部输入（EI）是由用户认可的唯一功能，通过这个功能数据或控制信息从应用程序的外部输入到应用程序中；数据指导致内部逻辑文件数据添加、修改、删除的数据；控制信息指激活/停止应用流程、影响数据传输处理的数据；常见关键字：新增、修改、删除、审核、审批、批阅、启动、停止、暂停、挂起、继续、调大小、注册、修改个人信息、修改密码、导入、批量删除、批量修改、数据清除，以及通过接口完成以上操作的功能 |
| 22 | 审计材料获取 | 功能项填报 | EO定义及识别规则 |  | 外部输出（EO）是由用户识别的穿越应用边界的独特的输出，它的数据需要进一步的处理；常见关键字：统计、报告、报表、分析、导生成*文件、报文、邮件、短信、指令，以及通过接口完成以上操作的功能 |
| 23 | 审计材料获取 | 功能项填报 | EQ外部查询定义 |  | 外部查询（EQ）是被用户认识到的独特的输入输出组合，在程序发布一个不需要进一步数据处理的输出；示例：人事系统中依据身份证号查询个人基本信息并展示，属于一对一查询，无数据处理，计为EQ；常见关键字：*查询、*详情、*查看 |
| 24 | 审计方法应用 | 审计流程-预审 |  |  | 1.审核材料齐套性，是否有缺失；2.审查合同单价，是否存在优惠打折等；3.审查送审金额是否超过订单金额；4.审查模版是否使用正确；5.技术规范书、交付规格说明书、费用功能清单三者是否功能模块结构逻辑一致 |
| 25 | 审计方法应用 | 审计流程-现场踏勘 |  |  | 1.依据技术规范书、费用功能点清单编写现场踏勘计划书；2.现场踏勘，拍照留痕；3.现场踏勘记录签字 |
| 26 | 审计方法应用 | 审计流程-正式评审 | 审计标准、方法 |  | 1.国家标准GB/T 36964-2018《软件工程 软件开发成本度量规范》；2.国家标准GB/T 42588-2023 《系统与软件工程 功能规模测量　NESMA方法》；3.CSBMK系列 中国软件行业基准数据 |
| 27 | 审计方法应用 | 审计流程-正式评审 | 评审流程步骤 |  | 1.审核费用功能点清单，得到审核结果；2.编写第三方工作量报告，编写三方定案表；3.第三方工作量报告、三方定案表、终版评审结果、现场踏勘记录签字文件上传系统；4.通知相关单位经理结果；5.如三方均无异议，则签订三方定案表，如有异议则进行二次送审 |
